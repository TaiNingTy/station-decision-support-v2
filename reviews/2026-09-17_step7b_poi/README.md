# 第 7b 步 · POI 层（2026-09-17）

目标是给 AI 解读层一个真实的设施层：每站三个环带内学校、诊所、杂货店、公园的数量与最近距离，只给数量与直线距离，不打分。计划时说学校、公园取县市开放数据，杂货店、诊所取 OSM；实际发现县 GIS 有官方的健康设施层，USDA 有 SNAP 零售商定位数据，两者都比 OSM 完整且有字段可依，所以四类全部改用官方来源，OSM 只作杂货店名单的交叉核对（Overpass 主站对 curl 返回 406，改用镜像，数据滞后已记录）。

## 获取与解析

- `scripts/fetch_miami_poi.py`：按研究窗口从 11 个图层服务取记录到 `raw/miami/2026-09-17/poi/`，每层记录服务 URL、字段、记录数、sha256、检索时间；`poi_acquisition_validation.json` PASS。
- `scripts/build_miami_poi.py`（阶段 `poi`，可选层）：规则固定在包内 `config.rules`。学校 = 公立在校生数 > 0 + 特许 + 私立；公园 = 市多边形 + 与之重叠不超过 50% 的县多边形；诊所 = 五层合并、50 m 内同名去重；杂货店 = SNAP 三种店型。点设施按落在环带内计数，公园按与环带相交计数；最近距离从 GTFS 参考点直线量到窗口内最近记录。输出画像、要素表（含被排除记录与原因）、逐条证据表、校验文件。

## 数值与语义

窗口内学校 37、诊所 8、杂货店 19、公园 38；全网 ½ mile 并集去重后 22 / 3 / 14 / 24。11 站 ½ mile 内没有任何来源中的诊所；每站 ½ mile 内都至少有一所学校、一家杂货店和一处公园。字段标 `observed / administrative_record`，`is_service_level_score: false`，`distance_type: straight_line`，缺失为 `not_found_in_source_within_window`。

## 接入方式

- 输入包每站每环带新增 `poi` 块（各类数量与设施 ID，证据指向），站级新增 `poi_nearest_by_category`；`optional_layers.poi` 为 `acquired`。
- 编排器在实测客流参照之后、输入包之前加入 `poi`；readiness 的 `ai_missing_optional` 只剩 `walk_model`。
- 上一轮修的"可选层后补要提示"当场生效：POI 包发布后、输入包重建前，readiness 把输入包标为 STALE 并点名 poi。

## 构建中发现并修正的三个问题

1. **学校规则的实现错误**：原判断"有在校生或有年级"，而县文件对教育局办公楼、车库、通信中心等填的年级是字符串 `'0'`，被当成"有年级"，8 条非学校记录进了学校类。改为只按在校生数 > 0，被排除的 8 条连同原因列在 `excluded_records`（含成人技术学院与两个零在校生的项目点；有在校生的虚拟学校保留，因来源未标注）。窗口内学校由 45 修正为 37。
2. **回归工具的路径缺陷**：这次把回归放到后台运行，临时目录落在 macOS 的 `/var/folders`（符号链接到 `/private/var`），站点主表脚本把未解析的脚本路径与已解析的根目录做相对化，4 个场景 38 项检查失败。之前的运行都在无符号链接的工作目录下，所以没暴露。修正：回归工具解析临时目录为规范路径，站点主表脚本解析自身路径。修正后在同样的符号链接目录下全部通过。
3. **就绪视图检查的过期期望**：`layers.pois` 现在应为 DONE，检查项已更新；三个用 poi 假包演示"可选层后补 / 损坏隔离"的场景改用仍未实现的 `walk_model` 假包。
